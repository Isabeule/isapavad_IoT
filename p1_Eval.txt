KUBERNETES ?
orchestrateur de conteneurs qui permet de déployer, exécuter, superviser et maintenir des applications 
conteneurisées sur une ou plusieurs machines. 
Il organise ces machines en cluster et gère notamment les pods, services, déploiements et le réseau.

K3s?
Distribution légère de Kubernetes. K3d est un outil qui permet de creer des clusters K3s a l'interieur 
de conteneurs Docker.
Elle fournit un cluster Kubernetes avec moins de composants et une installation simplifiée. 
Dans mon projet, je l’utilise directement dans des VM avec un Server et un Agent.

CLUSTER?
C'est un groupe de nodes (noeuds) qui travaillent ensemble.

NODE?
c'est le role de la machine lorsqu'elle appartient a un cluster Kubernetes.

kubectl get nodes -o wide ?
- kubectl = commande kubernetes pour envoyer des requetes a l'API Kubernetes. Ca sert a administrer ou
consulter le cluster.
- get nodes = afficher/recuperer des informations sur les ressources Kubernetes.
- nodes = la ressource demandee
- -o wide = pour demander une sortie plus detaillee. 
		ROLES control-plane,master = c'est le type de node. Ici, Server est celui qui pilote
						le cluster. c'est celui qui gere le cluster. Il recoit
						les commandes envoyees par kubectl. il connait tous les
						nodes, les pods et les services qui existent. Autorise 
						un Worker a rejoindre le cluster. Decide ou placer les 
						workloads, c-a-d les applications ou services que je 
						demandes a Kubernetes de faire tourner/executer.
		VERSION = version Kubernetes/K3s executee par les noeuds
		INTERNAL-IP = montre les adresses IP avec lesquelles les noeuds sont enregistres dans 
				K3s. Les 2 noeuds communiquent via leurs IP internes.
		OS-IMAGE = indique le systeme d'exploitation execute sur le node.
		KERNEL-VERSION = C'est la version du noyau Linux utilise par la machine.
		CONTAINER-RUNTIME = indique le moteur utilisé pour exécuter les conteneurs. 
					Ici K3s utilise containerd.

PODS?
Dans p1, il n'y a que des pods systeme crees automatiquement par K3s. Visibles ici:
vagrant ssh isapavadS
sudo kubectl get pods -A 
ou 
sudo k3s kubectl get pods -A

Comment fonctionne K3s dans P1 ?
Le Server K3s est installé sur isapavadS. Il crée le cluster et génère un token. 
Le Worker isapavadSW utilise l’adresse du Server et ce token pour rejoindre le même cluster comme Agent.

isapavadSW
192.168.56.111
      |
      | K3S_URL + K3S_TOKEN (voir scripts/agent.sh)
      v
isapavadS
192.168.56.110
      |
   K3s Server

Qu’est-ce que Vagrant ?
Vagrant sert a automatiser la creation de VM. On décrit les VM dans un Vagrantfile, 
puis vagrant up crée, démarre et configure l’environnement avec un provider de virtualisation (libvirt).

À quoi sert le Vagrantfile ?
Le Vagrantfile décrit l’infrastructure : image Linux, nombre de VMs, hostnames, IP, CPU, RAM, réseau 
et scripts de provisioning. Au lieu de configurer les VMs manuellement, je décris l’état voulu dans 
un fichier reproductible.

COMMANDE ip a = affiche les interfaces reseau d'une machine et les adresses IP qui lui sont attribuees.
eth0 = nom du reseau de gestion Vagrant et libvirt, c'est pour pouvoir communiquer via SSH notamment, et
aussi pour assurer le provisioning = configuration automatique d'une machine apres sa creation.
eth1 = nom de d'une interface reseau. l'adresse IP correspondante est celle utilisee par la machine 
pour communiquee avec l'autre machine. c'est l'adresse IP imposee dans le sujet.

COMMANDE ip route = pour demander par ou passent les paquets.
